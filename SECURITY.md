# Security policy

## Report privately

Do not open a public issue for a vulnerability, exposed credential, private URL,
personal information, or disclosure that could put users or infrastructure at
risk.

Use GitHub's private security-advisory channel:

https://github.com/Brehove/Your-Digital-Life/security/advisories/new

Include the affected commit or URL, reproduction details, impact, and any safe
mitigation you have identified. Do not include unrelated personal information.

## Supported version

Security fixes target the current default branch and the live production
version. Historical dataset releases remain immutable; if a release artifact
itself presents a security or privacy risk, the maintainer will document the
exception and remedial action.

## Response process

The maintainer will acknowledge a complete report through GitHub's private
advisory channel, investigate, coordinate a fix and disclosure when warranted,
and credit the reporter if requested and safe. Response timing depends on
severity and reproducibility; this project does not promise a fixed service
level.

## Scope

Reports about website code, build/deployment configuration, supply-chain risk,
or accidental disclosure are in scope. Disagreement with a published estimate
is not a security report; use the Data correction form. Harassment and Code of
Conduct reports may also use the private advisory channel when confidentiality
is necessary.
